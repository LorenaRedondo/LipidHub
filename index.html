Data architecture

From five fragmented sources to one queryable atlas

Nothing here needs to be invented from scratch — the reference data exists and ships with open licences and APIs. The work is reconciliation, enumeration, and inference, plus the two layers nobody has built: systematic synthesizability, and the gap map. Everything flows left to right; every value carries its provenance.

01 · INGEST

Reference sources

  • LIPID MAPS LMSD — ~48k curated
  • LMISSD + COMP_DB — 1.1M in-silico
  • SwissLipids — enzyme/pathway
  • Rhea · UniProt — reactions
  • HMDB · ChEBI — context & ontology
All open, all with bulk + API access.
02 · RECONCILE

Normalize & dedup

  • Canonical LIPID MAPS shorthand
  • InChIKey / SMILES identity
  • Cross-reference IDs across DBs
  • RDKit structure standardization
One species = one node, many sources.
03 · ENUMERATE

Define the space

  • headgroup × acyl-chain generator
  • chemically-sane bounds & rules
  • diff vs. curated → the gaps
This is what makes the "periodic table" complete.
04 · INFER

Property engine

  • RDKit — formula, mass, logP, TPSA
  • ML — CCS, RT, in-silico MS/MS
  • heuristics — Tm, packing
  • synthesizability — bio + chemical
Every gap gets predicted, testable properties.
05 · SERVE

Access layer

  • Postgres + RDKit cartridge
  • graph store for pathways
  • REST · SPARQL · bulk export
  • the Atlas UI (this)
Researchers meet it as UI, API, or download.

◧ core schema — provenance is a first-class citizen
-- one row per canonical species; identity by structure, not name
TABLE species (
  id            uuid PK,
  shorthand     text,        -- 'PC 34:1'
  lipid_class   text,        -- FK → class ontology (LIPID MAPS)
  n_carbon      int,  n_dbond int,
  formula       text,  exact_mass numeric,
  inchikey      text UNIQUE,
  origin        enum('curated','in_silico')   -- ← is it a gap?
);

-- every property value knows how it was produced
TABLE property (
  species_id    uuid FK,
  key           text,        -- 'ccs_mh', 'rt_rp', 'tm', 'logp'…
  value         numeric,
  method        enum('measured','calculated','predicted'),
  model_version text,        -- 'DeepCCS v2.1' — reproducible
  confidence    numeric,     -- ± interval
  source        text          -- DOI / DB accession
);

TABLE pathway  (species_id, enzyme_uniprot, rhea_rxn, direction);
TABLE synth    (species_id, bio_score, chem_sascore, route_json);
TABLE xref     (species_id, db, accession);   -- LMSD, SwissLipids, HMDB…

novel Synthesizability as a real column

No lipid DB systematically answers "can I make this?". We split it: a biosynthetic score (does an enzyme + pathway exist in SwissLipids/Rhea?) and a chemical score (SAScore/RAScore + a retrosynthesis pass, e.g. AiZynthFinder). That single distinction — nature-accessible vs. lab-accessible vs. neither — is defensible and, as far as the reference DBs go, unoccupied.

trust Predicted ≠ measured, always visible

Researchers won't adopt a black box. Every number in the inspector is tagged measured, calculated, or predicted, with the model version and an uncertainty interval. A value is a claim with a receipt — which is exactly what lets someone cite it, or decide to go measure it.

Who it's for

Five audiences, one atlas, five different front doors

The same data model serves very different jobs. The UI adapts what it surfaces — the "View as…" presets in the Atlas reorder the inspector so each user sees their numbers first.

◎

Mass-spec lipidomics analyst

core user · daily
The taskAn untargeted run throws an unknown feature at m/z 760.58, RT 11.3, CCS 301. Is it real, and what is it?
Search by mass or CCS window, land on candidate cells, compare predicted vs. their measured RT/CCS/MS-MS to confirm or reject an ID — including for species not in any spectral library because the atlas predicted them.
≋

Membrane biophysicist

research · project-driven
The taskDesign a model membrane with a target phase-transition temperature and curvature.
Filter the map by predicted Tm, logP, and headgroup geometry; see how one more double bond or two more carbons moves the property — the gradient across the grid is the structure–property relationship.
⚗

Synthetic chemist / biotech

discovery · high-value
The taskFind a novel lipid nanoparticle component that's chemically makeable but not naturally abundant.
Query the space directly: high chemical-synthesizability, low biosynthetic score — i.e. the white space of "lab-only" lipids — with a starting retrosynthetic route and the properties to prioritize candidates.
⌗

Bioinformatician / data scientist

integrator · programmatic
The taskAnnotate a 10,000-feature dataset and join lipids to enzymes for a network model.
Hit the REST/SPARQL API or bulk export; every species carries stable cross-refs (LMSD, SwissLipids, HMDB) and a provenance-tagged property table that's safe to build pipelines on.
⚕

Pharma / clinical researcher

translational
The taskA lipid biomarker moves in disease — what makes it, and is it druggable?
Trace a species to its biosynthetic enzymes and pathway, see structurally-neighbouring species that co-vary, and assess whether the pathway is a tractable target.
✎

Educators & students

reach · low-friction
The taskTeach why lipid diversity explodes combinatorially and where nature actually lives in that space.
The gap map is a teaching object on its own: the "periodic table" framing makes the enumerable space and nature's occupied subset visible at a glance.
Why this wins as a product, not just a database. LIPID MAPS and SwissLipids already own "the reference list." Competing on catalogue size is a losing game. LIPIDEX competes on integration + inference + the two missing layers (systematic synthesizability, and the explicit gap map) wrapped in a UI each audience can actually operate. The moat is the reconciled, provenance-tagged property graph — and the trust that comes from never hiding which numbers are predicted.
